# Make Events — Event Management System

A full-stack event management website for **Master Promote**, built with Django,
HTML/CSS/JavaScript, and SQLite (local) / PostgreSQL (production). It reproduces
every page and flow from the design prototype:

- **Home** — hero, features, "why choose us", featured events, testimonials, CTA
- **Events** — filterable grid (Event Type, Budget Range, Location, Venue) of 12 sample events
- **Event Detail** — services included, highlights, sample pricing, call/enquiry/booking actions
- **Book Your Event** — booking form saved to the database, viewable in the admin
- **Contact** — "Get in touch" form saved to the database + contact info panel
- **Services** — Wedding Planning, Corporate Event Management, Birthday & Private Parties, Cultural & Stage Programs
- **About Us** — story, mission, years of experience, team, "why choose us" grid

Every piece of text/image on these pages is editable from the Django admin — nothing
is hardcoded in the templates beyond structure.

---

## 1. Tech stack

| Layer      | Technology                                             |
|------------|---------------------------------------------------------|
| Backend    | Django 6.1 (Python 3.12)                                 |
| Frontend   | Django templates + vanilla CSS/JS (no build step needed) |
| Database   | SQLite (local dev) / PostgreSQL (production on Render)   |
| Static/Media | WhiteNoise (static), local filesystem (media)          |
| Deployment | Render (`render.yaml` + `build.sh` included)              |

No React/Bootstrap build pipeline is required — the CSS in `static/css/style.css`
is hand-written to match the prototype's palette and layout, and is fully responsive
out of the box (test down to ~360px wide).

## 3. Run it locally in VS Code

**Prerequisites:** Python 3.11+ installed.

```bash
# 1. Unzip and open the folder in VS Code
cd makeevents

# 2. Create and activate a virtual environment
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate

# 3. Install dependencies
pip install -r requirements.txt

# 4. Copy the env file (defaults already work for local SQLite)
cp .env.example .env

# 5. Run migrations
python manage.py migrate

# 6. Populate sample content (12 events, features, testimonials, team, services...)
python manage.py seed_data

# 7. Create an admin login
python manage.py createsuperuser

# 8. Run the dev server
python manage.py runserver
```

Visit:
- **Site:** http://127.0.0.1:8000/
- **Admin:** http://127.0.0.1:8000/admin/

### Replacing the placeholder images
`seed_data` uses generated placeholder photos in `seed_images/` (since the prototype's
real photography wasn't available to seed from). To use your real photos:
1. Log into `/admin/`, open **Core → Events / Team members / Testimonials / Site Settings**.
2. Replace each image field with your own photo, or
3. Swap the files in `seed_images/` and re-run `python manage.py seed_data` (safe to
   re-run — it uses `update_or_create` and won't duplicate records).

## 4. Deploying to Render

### Option A — One-click Blueprint
1. Push this project to a GitHub repository.
2. In the Render dashboard, choose **New → Blueprint** and point it at your repo.
   Render reads `render.yaml` and provisions:
   - a **Web Service** (Django + gunicorn)
   - a **PostgreSQL** database, automatically wired via `DATABASE_URL`
3. Render runs `build.sh` on every deploy, which will:
   - install dependencies
   - run `collectstatic`
   - run `migrate`
   - run `seed_data` (safe to re-run)
   - create a default admin user (`admin` / password from the `DJANGO_SUPERUSER_PASSWORD`
     env var, auto-generated by Render — check the Environment tab to see it, or set
     your own before the first deploy)

### Option B — Manual Web Service
1. **New → Web Service**, connect your repo.
2. Build command: `./build.sh`
3. Start command: `gunicorn config.wsgi:application --bind 0.0.0.0:$PORT`
4. Add a PostgreSQL instance and set `DATABASE_URL` to its connection string.
5. Set environment variables (see `.env.example` for the full list):
   - `SECRET_KEY` — any long random string
   - `DEBUG` — `False`
   - `ALLOWED_HOSTS` — `.onrender.com` (add your custom domain if you use one)
   - `CSRF_TRUSTED_ORIGINS` — `https://*.onrender.com`

### Notes on media storage
Render's filesystem is ephemeral — anything uploaded via `/admin/` under `media/`
will be lost on the next deploy unless you attach a
[persistent disk](https://render.com/docs/disks) or switch to an object storage
backend (e.g. AWS S3 / Cloudinary via `django-storages`). For a marketing site like
this where images change occasionally, either works fine; a persistent disk is the
simplest option — mount it at `/opt/render/project/src/media`.

## 5. Admin-editable content

Everything shown on the site lives in the database and is editable from `/admin/`:

| Model                  | Powers                                             |
|-------------------------|-----------------------------------------------------|
| `SiteSettings`          | hero text/image, about page copy, phone/email/address, social links |
| `Event`                 | every event card + its detail page                  |
| `Feature`                | "Our Features" cards on the home page                |
| `WhyChooseUs`             | "Why Choose Us" cards on the home page                |
| `Testimonial`             | testimonials list + avatars                            |
| `Service`                 | "Our Services" page rows                              |
| `TeamMember`              | About Us team grid                                    |
| `WhyChooseUsAbout`         | About Us "Why Choose Us?" tick cards                    |
| `Booking`                 | submissions from **Book Your Event**                    |
| `ContactMessage`          | submissions from **Contact → Get in touch**              |

## 6. Filters on the Events page

The Events page filters (`Event Type`, `Budget Range`, `Location`, `venue`) are plain
GET-parameter filters handled server-side in `core/views.py::event_list`, e.g.
`/events/?event_type=wedding&location=chennai`. They combine (AND logic) and can be
cleared with the **Clear Filters** button that appears once any filter is active.

## 7. Design tokens

The palette is defined as CSS custom properties at the top of `static/css/style.css`:

```css
--rose:   #a8828a;
--gold:   #f7cd64;
--cream:  #faebba;
--olive:  #948b6e;
--yellow: #ffcc4d;
--brown:  #997a2e;
--maroon: #5c1220;
```

Change these once and the whole site (buttons, section backgrounds, card borders,
footer) updates consistently.

## 8. Common commands

```bash
# Re-seed content after editing seed_data.py or seed_images/
python manage.py seed_data

# Reset all seeded content and reseed from scratch
python manage.py seed_data --flush

# Create/refresh the admin account
python manage.py createsuperuser

# Run the test server
python manage.py runserver

# Collect static files (needed before deploying manually)
python manage.py collectstatic
```
